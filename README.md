# Демо кассы

Локальный прототип кассы на React, Vite и shadcn/ui. Пользователь выбирает направление (Deposit / Withdraw), затем тип и способ оплаты. Для Польши демо предлагает BLIK, Przelewy24, Trustly, банковский перевод, карту, Paysafecard, Apple Pay, Google Pay и другие методы (PayPal, Skrill, Neteller). В текущей кассе выбран регион Польша. Доступные способы вывода зависят от региона и ранее успешно использованных способов пополнения. Есть также сценарий вывода криптовалюты.

Платежи, комиссии, лимиты, статусы и криптоадреса — демонстрационные. Адреса и QR-коды намеренно недействительны. Не вводите реальные платёжные данные и не отправляйте средства. Реальная доступность, суммы и реквизиты должны поступать от платёжного провайдера.

## Иконки и логотипы

- Для элементов интерфейса используйте [Lucide](https://lucide.dev/icons/) через `lucide-react`: навигация, раскрытие, копирование и статусы. Например, `ChevronDown` для раскрывающихся элементов и `ChevronRight` для перехода к способу оплаты. Сохраняйте единый размер и толщину линий; декоративным иконкам задавайте `aria-hidden`, а кнопкам с одной иконкой — доступное имя.
- Для брендов и платёжных методов используйте `@tabler/payments-react` и проверенные оригинальные логотипы, если точного бренда в библиотеке нет. Размещайте их в едином контейнере. Источники отдельных файлов описаны в [`public/payment-logos/ATTRIBUTION.md`](public/payment-logos/ATTRIBUTION.md).
- Не заменяйте фирменные платёжные знаки универсальными иконками, если доступен корректный логотип. Иконки интерфейса и фирменные знаки выполняют разные задачи.

## Storybook

```bash
pnpm storybook
```

Откройте `http://localhost:6006`: разделы Controls, Payment components и Screens показывают компоненты и состояния кассы. Истории в Cashier/Screens используют сам App. В `Cashier/Design system` есть референсный **Withdrawal flow**. shadcn/ui хранится в `src/components/ui`; настройки темы находятся в `src/index.css`. Новые состояния добавляйте в `src/stories` рядом с существующими историями.

### Дизайн-система Cashier

В Storybook есть отдельный раздел `Cashier/Design system` — тёмная кассирская система на основе флоу Phantom iOS «Adding funds». В ней: чёрный холст, спокойные поверхности, один лавандовый акцент `#AB9FF2`, серифный дисплей для суммы, нижние шторки и успех в контексте экрана.

- `Reference Flow` — интерактивный путь пополнения: хаб → сумма → способ оплаты → проверка → обработка → успех.
- `Amount Entry`, `Choice Cards`, `Payment Methods`, `Sheet`, `Review`, `Feedback`, `Empty States` — отдельные паттерны и состояния.
- `Entry Pattern` — общий развилочный сценарий «Add funds» с выбором cash/crypto. Крипто-карточка здесь визуальная: реальный адрес или QR-код не выдаётся и не имитируется.
- Тема ограничена классом `.cashier-ds`; все истории `Cashier/*` в Storybook уже рендерятся внутри `.cashier-ds` через декоратор preview, поэтому тёмные токены применяются ко всем разделам без перестройки layout. Живая касса в `src/App.tsx` перестроена на тех же примитивах (`CashierSurface`, `CashierHeader`, `OptionCard`, `MethodRow`, `AmountDisplay`, `SummaryList`, `StatusToast`, `ActionButton`); крипто-экран по умолчанию показывает иллюстративный адрес и QR. Данные для реального платежа должен выдавать провайдер.
- Комиссии, лимиты и время обработки в `Reference Flow` иллюстративные. В продакшене их должны приходить от платёжного провайдера.

Подробное описание токенов, компонентов, правил копирайта, доступности и внедрения — в [`DESIGN-SYSTEM.md`](DESIGN-SYSTEM.md). Исторические скриншоты референсного флоу — в [`reference/design-system/`](reference/design-system/).
